## 2. 模块边界与依赖规则

| 模块 | 职责 | 允许依赖 | 禁止 |
|---|---|---|---|
| S1 频道 | 频道 CRUD、权限关联查询 | S7 | 引用播单/会话内部实现 |
| S2 媒资 | 节目多维检索（一期 mock 数据源，C4） | — | 写操作 |
| S3 播单 | 播单增删调序清空、三种插入模式、版本号、线性时间轴（C1） | S1、S6、S7、WS 网关 | 直接访问 LLM |
| S4 会话 | 消息存档、分页、cutoff、规则对象存储 | S7 | — |
| S5 规则 | 三类规则存取、字段级增量覆盖、版本管理 | S7 | — |
| S6 编辑锁 | 抢占（原子）、心跳、30 分钟超时释放 | WS 网关 | 依赖任何业务服务 |
| S7 日志 | 追加写、检索；**不提供更新/删除接口** | — | 被业务服务同步阻塞（异步入队） |
| S8 LLM 网关 | DeepSeek 接入、敏感词过滤（G1）、超时降级（G6）、SLO 埋点 | S4（上下文检索） | 暴露 Key、直接写播单 |

**横切规则**：
- 所有写接口经「鉴权拦截器（C2：`X-User-Id` → 频道权限校验 G2）+ 锁校验（G3，仅播单/规则写）」两道前置
- WS 网关为独立基础设施模块，事件类型见 02 规格 §4
- 服务间只允许经 NestJS 模块 exports 的公开 service 调用，禁止跨模块 import entity

## 4. 工程约束

| 项 | 约束 |
|---|---|
| 运行时 | Node.js 22 LTS；包管理 npm；TS strict 模式 |
| 前端 | 不引入 UI 组件库（样式体系以 styles.css 为唯一基准）；不引入图标库（emoji 字符，B3） |
| 后端 | NestJS 10+、TypeORM、class-validator 入参校验；REST 统一响应 envelope（02 规格 §5） |
| 数据库 | PostgreSQL 15+；本地开发 docker-compose 起 PG；迁移用 TypeORM migration，禁用 synchronize |
| 密钥 | `DEEPSEEK_API_KEY` 仅存服务端环境变量；严禁入库/入前端/入 Git（.gitignore + 密钥扫描） |
| 日志 | 后端 pino；SLO 埋点集中在 S8（9.2 五项指标） |
| 测试 | Vitest（前端 store/工具函数）+ Jest（后端 service 单测）；AI 评估集脚本独立目录 `server/eval/` |

## 5. 部署形态（一期）

- 前端 `vite build` 静态产物，由后端静态托管或 nginx
- 后端单进程部署（8 服务为单体内模块，非微服务——一期无分布式必要，模块边界为未来拆分预留）
- PG 单实例；会话/日志表按月分区（O3 保存期限待定，先按 12 个月设计容量）
